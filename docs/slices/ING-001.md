# ING-001 - Upload Session and Source Record

**Status:** IMPLEMENTATION COMPLETE - pending independent review and `ACCEPT SLICE ING-001`  
**Version:** v1  
**Date:** 2026-11-23

## Outcome

Create an idempotent local-upload session and its corresponding source record with rights/provenance metadata. The API can list and retrieve that source record, but does not upload or persist media bytes in this slice.

## Parent requirements

- FR-001: Create a source-video record and upload supported files.
- FR-003: Record source, rights declaration, provenance and original metadata.
- FR-005: Resume or safely retry interrupted upload/ingestion.
- NFR-002: PostgreSQL is authoritative workflow state.
- NFR-003: Job dispatch and external side effects are idempotent/reconcilable.
- NFR-004: Credentials are never exposed to the browser or logs.
- NFR-005: Media is stored outside relational database blobs.

## Acceptance criteria

| ID | Given | When | Then |
|---|---|---|---|
| AC-ING-001-001 | Workspace source store is available | A valid local-upload request is submitted | The API returns HTTP 202 with one source ID and one upload-session ID, and both persist |
| AC-ING-001-002 | A valid upload session exists | The same idempotency key and identical payload are submitted again | The API returns the same source/session IDs with no duplicate source or rights record |
| AC-ING-001-003 | A used idempotency key is submitted with a different payload | Upload-session creation runs | The API returns HTTP 409 with a stable `IDEMPOTENCY_CONFLICT` error |
| AC-ING-001-004 | `rights_declaration=unknown_blocked` | Upload-session creation runs | The API returns HTTP 422 and does not create source/upload records |
| AC-ING-001-005 | One or more source records exist | Source list/detail is requested | The API returns workspace/source metadata and rights declaration without secrets or media bytes |
| AC-ING-001-006 | Upload-session fields are invalid | The endpoint validates the request | HTTP 422 uses the frozen `ErrorResponse` shape; no source or rights row is created |
| AC-ING-001-007 | Database store is unavailable | Upload-session creation runs | The API returns HTTP 503 with `SOURCE_STORE_UNAVAILABLE`; no success-shaped fallback |
| AC-ING-001-008 | Source record exists | Repository is re-read in a separate session | The persisted source and rights data are identical |

## Rollback

Downgrade or remove the ING-001 migration and repository/routes. No media, provider or external side effect exists in this slice, so rollback is limited to source metadata tables.

## Risks

- A duplicate idempotency key with different payload could corrupt source identity.
- Missing rights declaration could create unauthorized source records.
- SQLite tests must not become a claim for PostgreSQL migration behavior.
- A database outage must return an explicit 503, not a fake success.
- Source metadata must not include secrets or media bytes.
